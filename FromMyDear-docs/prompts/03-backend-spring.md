# Spring 백엔드 개발용 프롬프트

너는 숙련된 Spring 백엔드 엔지니어다.
첨부된 PRD, 데이터 모델, API 계약을 기준으로
연인 두 사람 전용 iOS 앱 ‘사이’의 백엔드를 구현해라.

계획만 작성하지 말고 현재 저장소에 실제 코드를 작성하고
로컬에서 실행·검증 가능한 상태로 완성해라.

[기술 방향]
- Java + Spring Boot
- Spring MVC, Spring Security, Bean Validation
- Spring Data JPA + PostgreSQL
- Flyway 데이터베이스 마이그레이션
- OpenAPI 명세
- 비공개 S3 호환 객체 스토리지
- APNs 푸시
- Gradle
- 로컬 실행용 Docker Compose
- 기존 버전이 있으면 존중하고, 신규라면 공식 지원 정보를 확인해 호환 버전 선택
- 초기에는 모듈형 모놀리스로 구성
- Redis, 메시지 브로커, 마이크로서비스는 필요성이 입증되지 않으면 추가하지 않기

[도메인]
- 사용자, 인증 세션, 기기 토큰
- 커플 공간, 멤버십, 초대
- 미디어, 일상 로그, 댓글, 반응
- 개인·공동 일정, 개인별 일정 알림
- 공동 목록, 항목
- 여행, 여행 일정, 준비물
- 일기
- 구절·단어
- 알림 설정, 무음 시간, 알림 발송 작업

[핵심 데이터 규칙]
- 한 사용자는 동시에 하나의 활성 커플 공간에만 속한다.
- 커플 공간의 활성 멤버는 최대 두 명이다.
- 초대코드는 만료·취소·재발급을 지원하고 무차별 대입을 제한한다.
- 코드 입력과 최종 연결은 기획서의 양측 확인 절차를 따른다.
- 동시 수락 요청에서도 멤버 수와 단일 연결 규칙을 지킨다.
- 애플리케이션 검증뿐 아니라 트랜잭션·제약조건·잠금으로 무결성을 보장한다.
- 개인 기록의 소유자와 공유 대상 커플 공간을 구분한다.
- 새로운 상대와 연결해도 과거 기록의 공유 대상을 자동 변경하지 않는다.
- 연결 해제 즉시 이전 상대의 API 접근을 차단한다.
- 공개 철회 후 상대가 상세 조회와 미디어 URL을 새로 발급받을 수 없어야 한다.
- 공동 데이터의 삭제·보관은 PRD의 정책을 따른다.

[인증과 권한]
- iOS 로그인 방식은 PRD를 따르고 Apple 로그인이 포함되면 서버에서 토큰을 검증한다.
- 인증 수단의 계정 연결 규칙을 명시한다.
- 액세스 토큰과 갱신 토큰의 만료·회전·폐기 정책을 구현한다.
- 갱신 토큰은 안전하게 저장하고 로그아웃 시 폐기한다.
- 모든 리소스 조회·수정·삭제에서 사용자와 커플 멤버십을 확인한다.
- 클라이언트가 보낸 userId 또는 coupleId만 믿지 않는다.
- 목록, 검색, 댓글, 미디어 경로에서도 동일한 권한 규칙을 적용한다.
- 다른 사용자의 객체 ID를 대입하는 접근을 차단하고 테스트한다.

[미디어]
- 업로드 준비 → 직접 업로드 → 완료 확인 → 처리 상태 → 게시 흐름 구현
- 허용 형식, 크기, 길이 검증
- 클라이언트가 업로드 성공을 주장하는 것만으로 게시하지 않기
- 미디어 처리 실패와 재시도 상태 정의
- 객체 스토리지는 비공개
- 재생 URL은 권한 확인 후 짧은 유효기간으로 발급
- 이미 발급한 URL의 만료 전 접근 한계와 보완책을 명시
- 미완료 업로드와 고아 파일 정리
- 대용량 미디어를 일반 API 서버 메모리에 통째로 적재하지 않기
- 실제 변환 작업을 구현하지 않은 경우 완료된 것처럼 표시하지 않기

[시간과 알림]
- 일반 시각은 UTC 기준으로 저장하고 사용자 IANA 시간대를 별도로 관리
- 종일 일정은 날짜 의미를 유지
- 자정 넘는 무음 시간, 요일 경계, 시간대 변경, DST 고려
- 알림 발송 시점에 사용자 설정과 현재 멤버십 재확인
- 무음 시간 처리 정책은 PRD 준수
- 알림 본문에 민감한 일기 내용을 기본 노출하지 않기
- 재시도로 인한 중복 알림 최소화
- 비활성 기기 토큰 정리
- 로컬에서는 실제 APNs 없이 검증할 수 있는 어댑터 제공
- 데이터 커밋과 알림 작업 등록 간 누락을 방지하는 구조 사용

[API 품질]
- 계약과 일치하는 REST API
- 일관된 오류 응답, 검증 오류, 권한 오류
- 목록 페이지네이션
- 영상 게시 등 중복 생성 위험이 있는 요청에 멱등성 적용
- 공동 목록·일정의 동시 수정 정책과 충돌 응답 구현
- N+1 조회와 불필요한 전체 조회 방지
- 요청 추적을 지원하되 인증 토큰·개인 기록은 로그에 남기지 않기

[개발 순서]
1. 프로젝트 기반, DB 마이그레이션, 오류 처리, 보안
2. 인증·커플 연결과 동시성 검증
3. 미디어·로그·댓글·반응
4. 일정·공동 목록
5. 여행·일기·문장
6. 알림·연결 해제·계정 삭제·파일 정리

- 실제 PostgreSQL 기반 통합 테스트를 우선 활용
- 동시 초대 수락, 세 번째 멤버 유입 차단
- 타 커플 데이터 접근 차단
- 비공개 일기와 공개 철회
- 연결 해제 후 접근 차단 및 재연결 시 과거 기록 격리
- 업로드 완료 검증과 중복 게시
- 무음 시간과 알림 중복 방지
- 공동 항목 수정 충돌

- 실행 가능한 코드와 DB 마이그레이션
- OpenAPI 명세와 iOS 연동 예시
- Docker Compose와 .env.example
- 실행·테스트·미디어·푸시 설정 README

기존 계약 변경이 필요하면 호환성 영향을 먼저 설명해라.
배포 비밀정보를 생성해 코드에 넣거나, 동작하지 않는 외부 연동을
완성된 기능으로 보고하지 마라.
