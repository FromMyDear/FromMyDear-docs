# 작업 규칙 (세 레포 공통)

## 브랜치

- `main`: 항상 빌드·테스트가 통과하는 상태
- 작업 브랜치: `feat/<짧은-설명>`, `fix/<짧은-설명>`, `docs/<짧은-설명>`
- `main`에는 PR로만 병합한다.

## 커밋 메시지

```
<type>: <요약>

feat     기능 추가
fix      버그 수정
docs     문서
refactor 동작 변화 없는 구조 변경
test     테스트
chore    빌드·설정
```

## PR 체크리스트

- [ ] 관련 문서(PRD, API_CONTRACT 등)와 일치한다
- [ ] 테스트를 추가·실행했다 (실행 못 한 검증은 PR에 적는다)
- [ ] API 계약을 바꿨다면 iOS·Server 영향을 적었다
- [ ] 비밀값·토큰·개인 데이터가 코드나 로그에 없다
